## 2024-05-15 - Interactive Elements Accessibility & Keyboard Handlers
**Learning:** Found a common pattern in the application's components (like NotificationCenter, Sidebar, AddScentModal, MediaSearchModal) where non-semantic elements like `<div>` were used for interactive popover triggers, completely bypassing keyboard accessibility. Furthermore, custom popovers frequently omit critical `Escape` key close handlers.
**Action:** When converting generic `<div onClick>` triggers to native `<button>` tags for accessibility, avoid using inline styles to reset default button appearances, as they can override necessary layout properties (e.g., `position: relative`). Instead, append reset properties (`background: transparent; border: none;`) to the element's existing CSS class. Additionally, ensure every modal or popover implements an `Escape` keydown event listener attached to the document or specific focus wrapper.
